# Движок разбора звонков

Берёт запись разговора, расшифровывает её, прогоняет по оценочной карте
и отдаёт HTML-отчёт на одной странице. Это ядро продукта, а не демо:
цифры в отчёте настоящие.

## Запуск

```
npm install
cp .env.example .env     # на Windows: copy .env.example .env
npm run analyze -- запись.mp3
```

Отчёт появится в `out/запись.html`.

## Что требуется

Всё закрывается одним облаком Яндекса. Ключ Anthropic не обязателен.

| Переменная | Зачем | Если не задана |
|---|---|---|
| `YANDEX_FOLDER_ID` | ID каталога, нужен в каждом запросе | ничего не работает |
| `YANDEX_STT_KEY` | распознавание записи | mock-режим: нужна готовая расшифровка рядом с записью |
| `YANDEX_GPT_KEY` | разбор расшифровки | разбор не запустится |
| `ANTHROPIC_API_KEY` | разбор через Claude вместо YandexGPT | берётся YandexGPT |

### У ключей Yandex Cloud есть область действия

Это главная ловушка. Ключ работает только для своей области — один ключ
на всё не годится:

| Область | Для чего |
|---|---|
| `yc.ai.speechkitStt.execute` | распознавание → `YANDEX_STT_KEY` |
| `yc.ai.languageModels.execute` | разбор → `YANDEX_GPT_KEY` |
| `yc.ai.speechkitTts.execute` | синтез, нужен для тренажёра |

Роль, выданная сервисному аккаунту, сама по себе не работает: к ней нужен
ключ с соответствующей областью. Роль без ключа — частая причина 403.

`YANDEX_FOLDER_ID` — это идентификатор каталога вида `b1g…`, а не его имя.
Имя «default» в адресной строке не подойдёт.

Mock-режим нужен, чтобы отлаживать разбор, не тратя деньги на распознавание.
Он не распознаёт звук и не делает вид, что распознал: берёт `запись.json`
рядом с файлом или `fixtures/sample.json`.

## Почему Yandex SpeechKit, а не зарубежный сервис

Запись разговора с клиентом — персональные данные по 152-ФЗ. Распознавание
внутри страны снимает вопрос трансграничной передачи. Зарубежный провайдер
потребовал бы отдельного согласия человека и уведомления Роскомнадзора.

Разбор по умолчанию тоже идёт в Яндексе — через YandexGPT. Тогда данные
не покидают страну вообще. Claude точнее, но это второй счёт и передача
текста расшифровки за границу; включается заданием `ANTHROPIC_API_KEY`.

Перед первым боевым клиентом текст договора и согласия должен посмотреть
юрист: здесь этого нет и быть не может.

## Как устроена защита от выдумок

Оценку ставит код, не модель. Модель расставляет вердикты по пунктам карты,
дальше работает `guard`:

- критерия нет в карте — вывод выбрасывается;
- вердикт `ok` или `warn` без дословной цитаты из расшифровки — снимается;
- цитата не находится в расшифровке — снимается;
- вердикт `bad` разрешён без цитаты: это утверждение об отсутствии, цитировать нечего;
- снятый вывод не исчезает, а становится «·» с пометкой, почему система отказалась утверждать.

Число снятых выводов печатается в отчёте. Это не украшение: клиент должен
видеть, где система промолчала, иначе ей нечего противопоставить вопросу
«а вы не придумали».

Оценка детерминирована: один и тот же набор вердиктов всегда даёт одно число.
Пункты `na` выходят из знаменателя — отсутствие данных не вина менеджера.

## Оценочная карта

12 пунктов, веса в `src/rubric.ts`. Менять можно, но каждая правка обнуляет
сравнимость с прошлыми замерами: это и есть причина, по которой карту
фиксируют до начала работы, а не подгоняют под результат.

## Тесты

```
npm test
```

24 теста: защита от выдумок, детерминированность оценки, момент потери,
экранирование разметки в отчёте и разбор ответа YandexGPT — она охотно
оборачивает JSON в ``` и добавляет фразы вокруг, поэтому парсер терпимый.

## Чего здесь нет

Регистрации, базы, многопользовательского режима, интеграций с CRM
и телефонией. Это консольный инструмент на одного. Веб-кабинет —
следующий шаг, и он имеет смысл только после первых платящих клиентов.
