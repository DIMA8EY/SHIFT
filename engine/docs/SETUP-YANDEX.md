# Голосовой тренажёр и распознаватель на Yandex Cloud

Инструкция под то, что есть: ключ Yandex Cloud и статический сайт
shiftagency.space. Ключ Anthropic не нужен — всё закрывается одним облаком.

---

## 0. Что сейчас на сайте

ИИ-агента на shiftagency.space нет. Единственная интеграция — телеграм-бот,
который пересылает заявки с формы (`script.js`, функция отправки формы).
Это не агент и не чат, это веб-хук на одну кнопку. Голосовой тренажёр
строится с нуля.

### Токен бота открыт

`script.js:12` содержит токен телеграм-бота в открытом виде. Файл отдаётся
всем посетителям сайта и лежит в публичном репозитории. Что с этим делать:

1. Отозвать токен у @BotFather: `/revoke` → выбрать бота.
2. Получить новый и **не возвращать его в `script.js`**.
3. Отправку формы перенести в прокси из шага 2 — там же, где будут ключи Яндекса.

Токен останется в истории гита даже после правки файла. Отзыв у BotFather —
единственное, что реально закрывает дыру.

## 1. Главное правило: ключ нельзя класть в сайт

Статический сайт — это файлы, которые браузер скачивает целиком. Весь
JavaScript виден через «Просмотр кода страницы». Ключ, положенный в JS,
становится публичным в момент публикации.

С ключом Yandex Cloud это дороже, чем с телеграм-ботом: по нему тратят
твои деньги. Распознавание и синтез платные, лимит — твой платёжный аккаунт.

**Поэтому между сайтом и Яндексом всегда стоит прокси.** Сайт зовёт прокси,
прокси знает ключ и зовёт Яндекс. Ключ не покидает сервер.

```
Браузер ──► Cloud Function (ключ здесь) ──► SpeechKit / YandexGPT
```

## 2. Что завести в Yandex Cloud

### Сервисный аккаунт

«Агентов» в Yandex Cloud нет — то, что ты ищешь, называется **сервисный
аккаунт**. Это учётка не для человека, а для программы.

Консоль → каталог → **Сервисные аккаунты** → Создать.

Выдать ему роли:

| Роль | Зачем |
|---|---|
| `ai.speechkit-stt.user` | распознавание речи |
| `ai.speechkit-tts.user` | синтез речи |
| `ai.languageModels.user` | YandexGPT — разбор вместо Claude |
| `storage.uploader` | загрузка записей в Object Storage |
| `functions.functionInvoker` | вызов функции-прокси |

### Ключ

У сервисного аккаунта → Создать новый ключ → **API-ключ**.

Показывается один раз, после закрытия окна не восстанавливается.

Бывает ещё IAM-токен — он живёт 12 часов и требует обновления. Для начала
не нужен: API-ключ проще и для SpeechKit с YandexGPT его достаточно.

### Что записать

- **API-ключ** — в переменные окружения функции, не в код
- **ID каталога** (`folder id`) — он не секретный, но нужен в каждом запросе

## 3. Прокси на Cloud Functions

Cloud Functions — это код без сервера: платишь за вызовы, а не за время
простоя. Живёт в том же облаке, что и ключ: один счёт, одна консоль.

Функция делает три вещи:

1. Принимает запрос от сайта
2. Подставляет ключ из переменной окружения
3. Зовёт SpeechKit или YandexGPT и возвращает ответ

Ключ кладётся в **переменные окружения функции**, а не в её код.

Что обязательно проверить в функции, иначе её используют чужие:

- откуда пришёл запрос (CORS только для своего домена)
- не слишком ли часто (иначе один скрипт выжжет весь баланс за ночь)
- не слишком ли большой файл

Без этих трёх проверок прокси — это тот же публичный ключ, только дороже.

## 4. Голосовой тренажёр

### Как не платить за то, что можно не платить

Реплики клиента в тренажёре **заранее заданы сценарием**. Значит синтезировать
их на лету незачем: озвучиваешь шесть реплик один раз, складываешь готовые
mp3 рядом с сайтом и проигрываешь как обычные файлы.

Синтез оплачивается один раз за всю жизнь тренажёра, а не за каждое занятие.

### Схема занятия

```
1. Браузер играет mp3 с репликой клиента        — бесплатно, файл статический
2. Браузер записывает ответ менеджера           — MediaRecorder, бесплатно
3. Так шесть раз
4. В конце одна отправка записи в прокси
5. Прокси: распознавание → разбор → вердикт
```

Распознавание включается **один раз в конце**, а не на каждую реплику.
Одно занятие — одна оплаченная минута распознавания вместо шести.

### Что нужно писать в браузере

- `navigator.mediaDevices.getUserMedia({ audio: true })` — доступ к микрофону
- `MediaRecorder` — запись ответов
- `<audio>` — проигрывание реплик клиента

Микрофон работает **только по https**. На локальном файле с диска он не
включится — нужен хотя бы `localhost` или домен с сертификатом.

### Разбор — это уже готовый движок

Шаг 5 не нужно писать заново: оценочная карта, защита от выдумок и расчёт
оценки уже есть в `engine/`. Тренажёр отличается от настоящего звонка только
тем, откуда взялась запись.

### Живой диалог — потом

«На Контроле» умеет отвечать на реальные слова менеджера. Это другая схема:
потоковое распознавание плюс YandexGPT плюс синтез на каждую реплику.

Минусы, которые надо знать заранее:

- платится каждая реплика каждого занятия, а не один раз
- задержка: пока распознали, подумали и синтезировали, проходят секунды,
  и разговор перестаёт быть похож на разговор
- потоковое распознавание идёт по gRPC, из браузера напрямую не работает —
  нужен постоянно работающий сервер, а не функция

Делать это стоит, когда тренажёром пользуются и за него платят. На запуске
сценарий по шагам даёт девяносто процентов пользы за три процента сложности.

## 5. Распознаватель загруженного звонка

Здесь всё проще, потому что ждать не нужно.

```
1. Менеджер выбирает файл на странице
2. Браузер грузит его напрямую в Object Storage по временной ссылке
3. Прокси запускает асинхронное распознавание
4. Готовую расшифровку разбирает движок из engine/
5. Отчёт на почту или на страницу
```

Файл идёт в хранилище мимо функции: у функции есть лимит на размер запроса,
а часовой разговор в него не влезет.

**Асинхронный режим дешевле потокового** и для загруженного файла подходит
лучше: никто не слушает запись в реальном времени.

## 6. Нужен ли Anthropic

Нет. В `engine/` разбор сейчас идёт через Claude, но это не обязательное
условие. YandexGPT умеет то же самое — расставить вердикты по пунктам карты.

Что меняется при переходе на YandexGPT:

| | Claude | YandexGPT |
|---|---|---|
| Ключи | второй ключ, второй счёт | один ключ на всё |
| Где считается | за границей | в России |
| 152-ФЗ | трансграничная передача текста | вопрос не возникает |
| Качество разбора | выше | ниже, но защита ловит выдумки одинаково |

**Защита от выдумок не зависит от модели.** Она сверяет цитаты с расшифровкой
кодом. Более слабая модель даст больше снятых выводов — и ты это увидишь
в отчёте числом, а не на ощупь.

Для старта бери YandexGPT: один ключ, один счёт, чистая юридическая история.
Переставить обратно — замена одного файла.

## 7. Сколько это стоит

**Точные цены я проверить не смог** — сайт Yandex Cloud из моего окружения
недоступен. Сторонние обзоры расходятся между собой, поэтому считать по ним
нельзя.

Открой официальный калькулятор и посмотри сам:
`yandex.cloud/ru/prices` — там SpeechKit и Foundation Models.

Что важно понять про единицы тарификации, прежде чем смотреть цены:

- распознавание считается **по времени аудио**, обычно блоками по 15 секунд
- асинхронное и отложенное дешевле потокового и синхронного
- синтез считается **по символам**, блоками примерно по 250
- у YandexGPT отдельный счёт по токенам

Прикинь по калькулятору две цифры: разбор одного часового звонка и одно
занятие на тренажёре. Этого хватит, чтобы понять экономику, и это десять
минут работы.

При создании платёжного аккаунта обычно дают стартовый грант. Проверь
в консоли — на отладку его хватит.

## 8. Порядок действий

1. Отозвать токен телеграм-бота у @BotFather
2. Завести сервисный аккаунт и выдать роли из шага 2
3. Создать API-ключ, записать ID каталога
4. Посмотреть цены в калькуляторе и посчитать два сценария
5. Прогнать настоящий звонок через `engine/` на своей машине
6. Поднять функцию-прокси
7. Озвучить шесть реплик тренажёра один раз
8. Собрать страницу тренажёра

Шаг 5 раньше шага 6 не случайно: пока не прогнан живой звонок, неизвестно,
что чинить. Поднимать прокси вокруг непроверенного разбора — работа вхолостую.

## Про персональные данные

Записи разговоров — персональные данные по 152-ФЗ, и чужие, а не твои:
они принадлежат людям, которые звонили.

Минимум, без которого нельзя брать записи клиента:

- письменное соглашение с компанией-клиентом до первой записи
- согласие на обработку от тех, чьи голоса в записи
- назначенный срок хранения и удаление после него
- письменное подтверждение удаления

Обработка внутри России снимает вопрос трансграничной передачи — поэтому
в схеме выше нет зарубежных сервисов.

Текст соглашения и согласия должен смотреть юрист. Здесь его нет и быть
не может: это инструкция по технике, а не юридический документ.
